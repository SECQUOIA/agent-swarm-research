# Development and review process

This paper is developed in six sequential stages. A stage is not accepted merely because its author finishes. The coordinator first assigns one author agent, then dispatches five independent reviewer agents after authoring is complete. The coordinator assesses every finding and records which criticisms are valid and which are major. A different agent fixes all valid findings, including minor findings. Any major finding triggers a new round of five independent reviews after correction. A stage closes only after a review finds no major issues and all remaining valid minor findings are addressed. The full manuscript receives this same cycle in Stage 6.

| Stage | Deliverable | Acceptance conditions |
|---|---|---|
| 1. Scope, prior work, and model semantics | Repository inventory; claim-to-evidence map; primary-literature comparison; introduction and exact-model contract | Novelty bounded by actual prior work; current evidence separated from prospective results; all implementation blockers recorded |
| 2. Certificate implementation and soundness theory | Corrected extraction/checker interfaces; proofs; adversarial regression tests; soundness and implementation sections | One coherent expression semantics; complete acceptance requires valid master-bound proof; malformed input rejected; claims match trusted components |
| 3. Focused Lean formalization | Lean proofs of safe affine correction and master-bound transfer; coverage statement and reproducible build | No unproved placeholders or additional axioms hidden in the proof; mathematical assumptions explicit; no assertion that Python or saved certificates are verified in Lean without an actual link |
| 4. Reproducible experiments and solver-claim audit | Frozen inputs; uniform new protocol; replay of available historical certificates under corrected semantics; generated tables and audit cases | Counts derived from saved records; failures included; production and checking costs separated; numerical primal values distinguished from verified feasible upper bounds; portable representative artifacts |
| 5. Integrated standalone manuscript | Complete LaTeX paper, bibliography, appendices and reproduction instructions | No research-note dependencies for understanding proofs; all claims supported; abstract and contributions match final evidence; compilation clean |
| 6. Whole-paper review and delivery | Five independent full reviews, coordinator adjudication, correction cycles, final PDF and source package | No unresolved valid major or minor issues in the assessed scope; final artifact and commands verified; limitations and remaining trust assumptions accurately disclosed |

The objective is a complete paper with a defensible scope, not an assertion that no future improvement or objection is possible. Missing functionality need not be added if the accepted manuscript makes no claim that depends on it. All substantive discovered errors must either be corrected or require the associated claim to be removed. If the whole topic is invalidated with no reasonable replacement contribution, record that finding and stop manuscript development.

Preserve unrelated work, including concurrent edits and new directories. Only the assigned stage files and explicitly assigned implementation changes may be modified. Do not delete historical evidence; label superseded results and write new verification records separately. The repository literature database has its own `literature/AGENTS.md`: its generated index and bibliography must not be hand-edited. The paper's selected bibliography is a separate editable file; do not redistribute user-supplied literature PDFs.
