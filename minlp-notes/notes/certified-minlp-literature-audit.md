**Certified convex MINLP: primary-source comparison and defensible contribution.**

Checked 2026-09-13. The repository has a plausible methods/software contribution in a replay interface that connects exact nonlinear model semantics, rigorous affine cuts, and a rational MILP proof. The existence of convex MINLP certificates, their computation and independent verification, outer approximation, safe rounding, and formal nonlinear bound checking are established topics. The earlier unsuccessful search for a MINLP certificate format does not support a novelty claim.

This is a focused primary-source audit, not an exhaustive priority determination. Searches included `Computing optimality certificates convex mixed integer`, `convex MINLP certificate interval`, `mixed-integer nonlinear proof VIPR`, `VIPR formally verified`, `CakeML VIPR checker`, and `discopt certificate MINLP`. The earlier paper evidence review supplied leads; the sources below were reopened and checked. For the closest article, the accepted manuscript's assumptions, verification algorithm, and computational-study description were inspected. For current software, repository files were inspected at pinned commits. No external project was installed, modified, benchmarked, or contacted in this audit.

**A current adjacent implementation that must not be overlooked.**

The 2026 `discopt` project documents interval-based curvature certification, MINLP bound/gap reporting, and safe LP bound/Farkas checks. These are adjacent capabilities, so claims that MINLP checking does not exist are especially inappropriate. Its [convexity documentation](https://kitchingroup.cheme.cmu.edu/discopt/notebooks/convexity_detection.html) describes interval differentiation and Hessian tests; this audit records those as project claims, not an independent validation of its arithmetic.

At commit `66d341df0ab8da383f97207f9f3f4145d9789b4b` (2026-09-12), the inspected [reformulation certificate module](https://raw.githubusercontent.com/jkitchin/discopt/66d341df0ab8da383f97207f9f3f4145d9789b4b/python/discopt/decomposition/ir/certificate.py) treats its certificate as advisory and the solver result as authoritative. Its postcondition checks the presence of a finite bound when required. That module does not implement independent replay of a nonlinear-to-rational-MILP proof object. The inspected [LP certificate tests](https://raw.githubusercontent.com/jkitchin/discopt/66d341df0ab8da383f97207f9f3f4145d9789b4b/python/tests/test_lp_certificates.py) exercise safe dual bounds and Farkas checks within solver operation. These observations distinguish the reviewed components; they do not prove absence of another interface elsewhere in that evolving repository. The official repository tree was searched for certificate/proof/VIPR paths to select these files. No claim about the correctness or completeness of `discopt` follows from that limited inspection.

**The contribution that can be supported after corrected replay.**

A defensible description is: an implemented, auditable pipeline for checking lower bounds on an explicitly interpreted class of algebraic convex MINLP models, combining a common exact expression interpretation, conservative affine underestimators, explicit model-to-master identity, and replay of rational MILP proofs. Its empirical contribution is the measured coverage, bound quality, verification cost, and failure behavior of that pipeline on identified artifacts. This is a concrete description, not a claim of priority.

The supporting-hyperplane inequality, half-line residual-slope conditions, epigraph transformation, and feasible-set inclusion are elementary tools. Their value here is making the interface precise and exposing errors at its boundaries. Shared exact semantics and adversarial replay tests can make the software contribution credible, but do not by themselves establish a new theoretical result. The corrected [soundness note](certified-minlp-soundness.md) separates the mathematical theorem from the software obligations.

Any future manuscript should distinguish three meanings of certificate: a mathematical witness whose conditions are solved or checked; a saved proof object that is replayed without rerunning the original optimization; and a proof object checked by an implementation with a specified formal verification theorem. Calling all three simply certified obscures the relevant comparison. Neither a checked master incumbent nor a recorded MINLPLib objective is an independently checked nonlinear primal certificate.

Priority wording, if used at all, must be restricted to the exact combination actually implemented and supported by the searches. Prefer describing that combination directly. The audit does not support claims of first convex MINLP certificates, first independent optimality verification, first rigorous cuts, first nonlinear formal verification, first verified MILP checking, no trusted code, end-to-end Lean verification, general finite termination, polynomial certificate size, or performance superiority.

For the current lower-bound scope, replacing the MILP checker by a formally verified backend is an optional extension. The required work is a correct, explicit checking contract and validated replay with its trusted components disclosed. Claiming that any future checker eliminates the full trust base would still require a separate proof connecting input parsing, nonlinear semantics, arithmetic enclosures, and the checked discrete problem.
