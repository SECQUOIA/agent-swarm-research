# Certified MINLP: claim-to-declaration map

This table maps all 49 mathematical obligations in [CLAIMS.md](CLAIMS.md) to
the standalone Lean package. Names are in `CertifiedMinlp` unless a nested
namespace is shown. A linked module locates the declarations in that row.
The three existing modules, `Coordinates`, `SafeCuts`, and `Transfer`, are
reused; the other modules extend their coverage.

The mapping describes mathematical coverage, not verification of the Python
implementation. Local check results belong in [VERIFICATION.md](VERIFICATION.md).
All 49 rows identify proved mathematical results. The final integration review
confirmed CM31–CM32, including the affine and matched-master cases. No
project-wide verification or CI status check is required locally.

## Representation and software boundary

The uniform graph encoding always appends both auxiliary coordinates. With an
exact affine objective the epigraph coefficient is zero. This harmless unused
coordinate is a mathematical representation choice, not a claim about which
variables the Python exporter allocates. The master matcher receives a typed
Lean equivalence and checks a row-scaling witness; it does not verify string
names, prefix handling, or canonical-scale construction. Both masters already
use the normalized minimization convention. A textual objective-sense token
remains a parser obligation.

The integration proves validity of every included master row. It does not
require every possible source restriction to be present, because omitting a
valid restriction weakens a relaxation and preserves the lower-bound
implication. The separate matching theorem does check both supplied row lists
with multiplicity, so no row may disappear between those two masters.


| ID | Coverage status |
|---|---|
| CS01 | **Python/model extraction not formally verified.** The arithmetic identities, support calculus, and expression-domain counterexamples are mathematical results. They do not prove Pyomo/SymPy interpretation or the loader's behavior. |
| CS02 | **Interval-library execution not formally verified.** Exact rational arithmetic, dyadic interpretation, and comparison implications are formalized; actual mpmath transcendental enclosures and endpoint extraction remain trusted inputs. |
| CS03 | **Python refinement not formally verified.** The Lean propagation relation, curvature results, cut evidence, and master witness checker prove their own meanings. They do not establish that Python implements them. |
| CS04 | **Structured Lean checker verified; Python/VIPR text parser not formally verified.** `Discrete.checkBound` validates typed rational solutions and the whole typed derivation. ASCII syntax, duplicates in raw input, section counts, lifetimes, `global` metadata, EOF, python-flint, and mutable streaming storage remain outside that theorem. |
| CS05 | **Lean acceptance implication verified; public Python API not formally verified.** `checked_bound` requires `checkBound = true`. It does not prove all Python error and partial-mode control paths. |
| CS06 | **Streaming implementation and physical memory representation not formally verified.** The Lean checker processes a finite structured list; it is not a proof of the Python two-pass memory accounting or liveness implementation. |
| CS07 | **Operational provenance and execution assumptions not formally verified.** Hashing, subprocesses, manifests, timeouts, stable files, and external-checker corroboration require their own software evidence. |
| CS08 | **Historical, empirical, and literature claims not Lean-verified.** No benchmark certificate, timing, test count, external-checker history, or priority assertion is certified by this mathematical package. |

Consequently, completion of the mathematical inventory means that the listed
mathematical implications and the stated structured Lean checkers are proved.
It does not mean that the complete deployed certificate pipeline, source
models, or benchmark bundles have been verified by Lean. [REVIEW.md](REVIEW.md)
records the semantic review; [VERIFICATION.md](VERIFICATION.md) records the
targeted validation actually performed.
